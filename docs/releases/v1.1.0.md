## Compatibility and claim boundaries

- Span values accept Python `int`/`float` scalars only, excluding booleans;
  `halls` and active cut degrees must be integers. Latency and bandwidth must be
  finite and nonnegative, with positive bandwidth for an active span. Halls
  cannot exceed the named degree. Nondivisible cuts keep the existing
  ceiling-sized local-group approximation; this is not a physical layout proof.
- YAML 1.1 scientific notation without a signed exponent can parse as text.
  Span fields and active degrees no longer coerce strings. For a bandwidth,
  write `400` or `4.0e+2`, not `4e2` or a quoted numeric string. Integer halls
  and active degrees require YAML integers, not `2.0` or `"2"`.
- The generation-sensitivity study holds an H100-class tp8/pp16 plan fixed.
  `memory_gb` does not enforce shard fit; there is no memory-capacity feasibility
  search or automatic plan reoptimization. Changing hardware declarations does
  not establish feasible execution or a cross-generation purchasing result.
- Span bandwidth is aggregate capacity shared by crossing groups. Reported
  atlas retention is limited to circuits at or below 3.2 Tbit/s; above-ceiling
  crossover is a tier-model artifact, not a deployment recommendation.
- The optional applicability gate checks static declarations for the existing
  flat-switched abstraction. It rejects unsupported precision/topology and
  ambiguous units or directions; it neither verifies evidence authenticity nor
  calibrates, authorizes, invokes or automatically configures model execution.
  Host, SRAM, topology calibration, power and price can remain unknown.
- WAN outputs are bounded analytic scenarios, not convergence or production
  reliability proof. Disconnected provenance and nonfinite-output refusal are
  corrected here. `required_bandwidth` bisects linearly 70 times, so its width resolution is
  about `maximum_gbps / 2^70` (about `8.5e-22` of the bound). The default
  `maximum_gbps=1e6` gives resolution about `8.5e-16` Gbit/s, far below a
  practical width. At `maximum_gbps=1e300`, the default workload with target
  useful-compute fraction 0.5 returns about **8.5e278 Gbit/s in every regime**.
  The default-bound minima instead differ: approximately 48.701 synchronous,
  0.070133 periodic, 50.095 hierarchical and 0.035033 decoupled Gbit/s. The
  huge-bound answer is feasible but conveys no useful minimum-width information;
  keep the search bound near the expected answer. This pre-existing algorithm
  is unchanged here. Tiny nonzero health can also produce astronomically large
  yet finite modeled communication times; finiteness is not operational feasibility.

Reproduce the synthetic inversion disclosure without changing source or artifacts:

```python
from netcap.wan import WANWorkload, required_bandwidth
w = WANWorkload()
for regime in ("synchronous", "periodic", "hierarchical", "decoupled"):
    print(regime, required_bandwidth(w, 0.5, regime),
          required_bandwidth(w, 0.5, regime, maximum_gbps=1e300))
```

clinical/defence/finance safety claim follows from this candidate.
